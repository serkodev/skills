# Code Comments

Use comments only to explain non-obvious rationale, constraints, invariants, or tradeoffs necessary to understand the current code.

Keep comments concise and focused, typically one or two lines. Longer comments are justified only when essential context cannot be conveyed more concisely.

Do not use comments to document:

- intermediate attempts
- rejected approaches
- previous agent mistakes
- changes made and then reverted during the same task
- facts already obvious from the code

Explain why the current code is the way it is, not how we arrived there.
